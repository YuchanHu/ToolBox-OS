# ToolBox OS · 多品牌常亮灯控制：本地接手任务书

## 任务目标

接手当前分支 `feature/multi-brand-lighting` 的增量开发，不从零重写。以 Multi-brand-light-link v1.0.20 APK 静态逆向结果为基线，完善面向 M5Stack StopWatch（ESP32-S3）的独立、多品牌常亮灯 App。先完成全部可基于静态证据的开发及离线测试，输出完整可刷机固件；之后由用户按品牌、型号一次性集中验收，拿到记录再进行针对性修正。开发期间不要求用户连接灯具、抓包或反复刷机。

## 先阅读

- `docs/LIGHTING_PROTOCOL.md`：本轮实现范围、品牌映射、验收步骤、刷写条件。
- `docs/lighting/APK_ANALYSIS.md`：APK 来源、资产/原生桥接、静态证据与已知未完成项。
- `reference/lighting/README.md`：上游 APK、许可证与参考材料获取方式。
- `docs/lighting/BUILD_RESULT.md`：云端首版编译及离线测试结果。
- `main/apps/app_lighting/`、`main/system/lighting/`、`tools/lighting-test/`。
- 根目录 AGENTS.md（如存在）、README、`docs/BUILD.md`、现有相机控制 App、蓝牙生命周期和应用注册代码。

## 既有工作（不重复实现）

- 11 个协议族；BLE 广播、GATT、BLE Mesh（标准配置和厂商模型）。
- 灯位保存、连接/入网、控制界面、基础模式和能力表已接入。
- 44 组由 APK 协议函数导出的离线向量全部通过，已完成 ESP-IDF 5.5.5 固件编译。
- 云端首版仅是待实体灯验证的工程实现，并非已确认所有型号可用；尤其需要核对 Mesh 入网、密钥绑定、广播时序、通知和 GATT 写入方式。

## 本地继续开发

1. 检查本地工作树及当前 HEAD。确保现有未提交修改不丢失；把本开发分支接入用户当前工作基线，若发生与后来开发的相机、引闪等冲突，最小范围解决，不覆盖其他功能。
2. 使用本地已有 ESP-IDF 5.5.5、VS Code 环境。按 `reference/lighting/README.md` 获取并解包指定版本的 APK，必要时使用 JADX 核对原生协议逻辑。将参考文件留在本地构建目录。
3. 对当前编码、设备识别、GATT 服务/特征 UUID、连接/断连、通知、写入类型、MTU、广播地址/间隔、Mesh 入网/配置/模型识别、同一控制器的多灯位隔离逐项静态核对。以 APK 事实为准；不要把所有品牌笼统当成 GATT。记录每项协议事实与对应 APK 文件、函数和证据。
4. 补齐确有静态证据的缺项。重点是影器、永诺、爱图仕/amaran；其次金贝、神牛、印迹、南光、新摄角、轻装时代、Ulanzi、智云。南光 Feasy Mesh / Netrix 目前缺失，金贝 Pairlink 流程尚未实现。飞面/过曝不在当前 APK 的可识别协议内，需要独立 APK/协议材料后才开发，不得虚构报文。
5. 延用原有圆形 466×466 屏幕 UI、MiSans、现有应用导航/振动反馈。优先复用相机控制类通用组件，不照搬 Android UI，不使用图片模型生成 UI；禁止无意义的小字和提示，不过度防御。提供实际 UI 渲染预览（使用本项目已有渲染方式），确保文字、布局无截断；不擅改其他 App。
6. 保持已有单 Factory 分区布局，严禁任何 App 后台运行。灯控离开 App 后停止发送、扫描、连接和 Mesh 活动；切换灯位、退出、蓝牙开关及相机控制不相互干扰。不能仅凭 Flash 充足判断 RAM 足够，关注 PSRAM、内存峰值、连接/入网资源释放和 BLE 共用生命周期。
7. 运行现有 44 组测试，新增与修复或新协议相对应的离线向量，不为通过测试而修改预期值。编译整个固件：`idf.py -B build-toolbox build`。检查固件体积、分区余量、链接结果、警告和原有功能回归。禁止反复进行无意义哈希校验。软件验证与实机验证分开记录。
8. 完成后输出一次完整固件 `build-toolbox/ToolBoxOS.bin`，更新协议文档、构建结果、实机验收矩阵（逐品牌/型号、发现/连接/配对/开关/亮度/CCT/HSI/G-M/灯效/重连/跨 App）。实体灯验收由用户统一进行；明确哪些属于静态实现、哪些已有硬件证据、哪些未实现。未经用户验收，不宣称“支持所有型号”或“实机已通过”。

## 交付标准

完整可编译的固件、合理的 UI、所有已有离线向量通过、协议与已知限制有据可查、测试步骤清晰。集中实机验收后再按反馈修正，不需要逐品牌中断开发等待试灯。不要自动合并主分支或推送未获授权的更改。
